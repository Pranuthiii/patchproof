PatchProof

AI fixes that show their receipts. Runs that produced a patch were judged by a verifier and a hidden oracle test the AI never saw. Runs that ended earlier never reached the oracle.

What this project found

  • One-shot fixes can hide real flaws. Four NVIDIA Nemotron models patched code in a single call with no test. On the common flaws (cases 01, 02, 04, 05, 06), 99 of 100 patches were verified. On open redirect (case 08), all 20 patches passed the ordinary tests and failed a hidden oracle test.
  • A hidden oracle catches what ordinary tests miss. Across cases 03, 07 and 08 it flagged patches that looked correct and were not.
  • The retry loop with an AI-written test did not help in these experiments. Super and Ultra on five cases, five runs each: 33/50 verified against 36/50 one-shot, with overlapping 95% intervals, at about ten times the tokens.
  • Why: the AI-written attack tests cover attacks the model already knows. The case 08 tests we inspected did not include the ///evil.test form the oracle uses.
  • What verified means. In this benchmark it means the AI's test, the existing tests and a hidden oracle all passed. On real code there is no hidden oracle, so a verdict is only as strong as the AI-written test.

Small samples: five runs per cell, eight hand-built cases. These are measurements of this setup, not a general benchmark.

Featured runs

  • case01_sqli_super_2 (single agent)
    Verified. The AI's attack test failed on the vulnerable code, the patch passed it, and the hidden oracle confirmed the fix.
  • case03_prefix_traversal_super_2 (single agent)
    False fix. The patch uses a plain startswith check, so a sibling folder such as files_private still passes. The AI's own test only tried ../secret.txt, so it passed, but the hidden oracle failed the patch.
  • case03_prefix_traversal_lightning_1 (single agent)
    Truncated. The model's reasoning hit the 16,000-token output limit before it finished a test, so there is no usable test or patch.
  • case04_orderby_injection_super_2 (loop agent)
    Retry rescued the run. The first test only checked that an unknown column raises ValueError, which is not an injection test, and was rejected. The second attempt used a weaker username-DESC test. The hidden oracle, which tries canary payloads, confirmed the final patch.
  • case04_orderby_injection_nano_2 (loop agent)
    Rejected after a retry. Neither attempt produced a test that failed cleanly on the vulnerable code, so the run stopped before any patch.
