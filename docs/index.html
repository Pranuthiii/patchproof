What we found

One-shot fixes pass easy cases and fail subtle ones

99 of 100 patches were verified on five common flaw types. On open redirect, 20 of 20 passed the existing tests and failed the hidden oracle.

A hidden oracle catches what ordinary tests miss

On the prefix-traversal, HTML-escaping and open-redirect cases it flagged 33 patches that looked correct and were not.

An AI-written test and retries did not measurably help

Lightning, Nano, Super, Ultra on 8 cases: 112/160 verified with the loop against 126/160 one-shot. The 95% intervals overlap slightly, so we cannot call it worse, but it was not better, at about 12x the tokens.

Why the AI-written test is the weak link. It covers attacks the model already knows. The open-redirect tests we inspected did not include the ///evil.test form the oracle uses.
A negative result we kept. We also tried asking the model to red-team its own patch. In the one run we inspected it invented bypasses that were really the allowed host, so we did not pursue it.

How it works

Every run follows the same pipeline.

  1. Finding

    A plain-English description of one vulnerability and the function it affects.

  2. AI writes an attack test

    A Nemotron model writes a test that must fail on the vulnerable code.

  3. AI writes the patch

    The model edits app.py only, and may retry using the verifier's output.

  4. Sandbox verifier

    Plain code runs every test in Docker: no network, read-only files, dropped privileges.

  5. Hidden oracle

    Benchmark only: a hand-written test the model never sees has the final say.

Under the hood

Models

  • NVIDIA Nemotron Lightning, Nano, Super and Ultra, through the Nebius Token Factory API.
  • Tool calling worked on all four. Reasoning tokens count against the output cap.

Sandbox

  • Docker with no network, a read-only root filesystem, dropped Linux capabilities and a non-root user.
  • Memory, CPU and process limits, plus a 45 second timeout inside the container.

Verifier

  • Plain code decides pass or fail, never the model.
  • Test files are hash-checked so a patch cannot edit the tests it is judged by.

Tavily

  • A runtime web search adds advisory context to the test-writer in one agent variant.
  • In a 12-run test on one case the results were mixed, so we report no measured benefit.

Evidence

  • Every result file, the eight cases and their reference fixes are in the repository.
  • Read the full summary table.

Limits

  • Small samples: five runs per cell and eight hand-built cases. These measure this setup and are not a general benchmark.
  • In the benchmark, verified means the AI's test, the existing tests and a hidden oracle all passed. On real code there is no hidden oracle, so a verdict is only as strong as the AI-written test.
  • Ultra was available when its runs were made but was no longer listed on the account when checked on Oct 13, 2026.
  • The early experiments used the API's default temperature, where Super sometimes returned identical replies. The main evaluation used temperature 0.7.
  • Truncated means the model hit the 16,000-token output limit set by the test harness.
  • This page shows recorded runs. The agent itself runs locally with Docker.
